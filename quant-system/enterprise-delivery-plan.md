# 企业级交付计划（你我分工版）

> 目标：按企业级方法，把 A 股无图形量化系统从 0 到 1 稳定落地。

## 1. 交付原则（企业级）

1. **需求先行**：每个迭代先冻结需求范围
2. **契约驱动**：先定义 API/Schema，再开发实现
3. **质量内建**：测试、日志、监控、回滚从第一天开始
4. **小步快跑**：每周有可验收成果
5. **可追溯**：每个策略、任务、数据版本可审计

---

## 2. 你和我的角色分工（RACI 简化）

## 2.1 你（业务Owner）负责

- 明确策略业务目标（收益目标、风险偏好、调仓频率）
- 定义可接受的风控边界（最大回撤、单票仓位、行业暴露）
- 对每个里程碑做验收（是否“可用”）
- 决策优先级（先做什么、延后什么）

## 2.2 我（技术Owner）负责

- 系统架构设计与技术方案落地
- API/Schema/数据库模型设计
- 数据接入、回测执行、调度链路实现
- 测试方案、质量门禁、发布流程建议
- 把你的自然语言策略转成结构化配置

## 2.3 共同负责

- 每周评审：结果复盘 + 下周范围确认
- 变更管理：策略规则和指标口径变更记录

---

## 3. 第一个月执行计划（按周）

### Week 1：项目治理与接口冻结

**目标**：建立“可持续开发”的基线。

- 输出 v1 业务需求文档（BRD）
- 输出 v1 API 合同（OpenAPI）
- 输出 v1 策略 Schema（JSON Schema）
- 定义日志规范、错误码规范、配置规范

**验收标准**：

- 你确认 BRD 与 API 字段不再频繁改动

### Week 2：数据层稳定化

**目标**：数据可靠可用。

- 完成 A 股日线增量同步流程
- 增加数据质量检查（缺失值、重复、交易日连续性）
- 增加数据作业日志与失败重试

**验收标准**：

- 指定 20 只股票可稳定查询且口径一致

### Week 3：策略与回测闭环

**目标**：从配置到结果打通。

- 策略 CRUD + validate
- 回测任务 API + 结果报告 API
- 回测指标统一（收益/回撤/换手/成本）

**验收标准**：

- 你可提交一条策略配置并拿到可读报告

### Week 4：运行与运维基线

**目标**：可运行、可观察、可恢复。

- 定时运行（周频/日频）
- 运行日志与任务状态看板（先日志版）
- 基础备份与恢复演练

**验收标准**：

- 连续 5 天任务稳定执行

---

## 4. 开发流程（你无需写代码也能推进）

每个需求都走 5 步：

1. 你提业务目标（自然语言）
2. 我转成“结构化需求卡”
3. 你确认范围与验收标准
4. 我实现 + 测试 + 交付说明
5. 你验收并决定下个迭代

---

## 5. 文档与资产清单（必须持续维护）

- `BRD.md`：业务需求
- `api-contract.yaml`：接口合同
- `strategy-schema.json`：策略结构
- `runbook.md`：运行手册
- `changelog.md`：变更记录

说明：后续 UI 接入时，以上资产可直接复用。

---

## 6. 第一批“马上执行”的决策项（你来拍板）

1. 初始调仓频率：周频 or 日频（建议周频）
2. 初始风控底线：最大回撤阈值（建议 12%）
3. 数据复权口径：前复权 qfq 是否固定（建议固定）
4. 首个验收策略：价值/趋势/混合（三选一）

---

## 7. 我们的协作节奏（建议）

- 每周 1 次里程碑评审（30~45 分钟）
- 每次只推进一个主题（数据/策略/回测/调度）
- 每次产出都具备“可演示、可验收、可回滚”

一句话：你负责“方向与验收”，我负责“实现与质量”。
