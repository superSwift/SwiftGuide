# A股量化系统开源平台选型与集成方案（系统优先）

> 目标：先搭一个“可手动编辑策略 + 可回测 + 可运行”的系统，再逐步加入自然语言转策略能力。

## 1. 你这个思路是对的

可以不急着进入“具体策略”本身，先把系统搭起来：

1. 可视化/半可视化策略编辑
2. 回测执行与结果分析
3. 数据源与数据库稳定运行
4. 运行调度（每日/每周）

系统稳定后，再加“你说自然语言，我帮你转规则”的能力。

---

## 2. 优先考虑的开源项目（A股友好度）

## 2.1 Qlib（微软）

- 定位：研究与模型平台，因子研究与机器学习能力强
- A股适配：较好（社区常用于 A 股）
- 优点：
  - 完整研究流程（数据->特征->模型->回测）
  - 适合后续从规则扩展到 ML
- 缺点：
  - 上手复杂度较高
  - 对“纯界面化手工编辑策略”不够友好

**结论**：适合作为“二期研究引擎”，不建议作为一期唯一入口。

## 2.2 vn.py + vnpy_ctastrategy / vnpy_portfoliostrategy

- 定位：偏交易执行和策略运行框架
- A股适配：依赖具体网关与数据接入
- 优点：
  - 事件驱动稳定
  - 接近实盘运行模式
- 缺点：
  - 策略通常仍需写代码
  - 对新手门槛较高

**结论**：适合未来实盘或半实盘阶段，不是当前“零代码优先”的最佳起点。

## 2.3 Backtrader（+ 自建参数化策略编辑）

- 定位：成熟回测引擎
- A股适配：可行（需自己处理 A 股数据细节）
- 优点：
  - 社区成熟、文档多
  - 规则策略实现快
- 缺点：
  - 本身不带完整可视化策略编辑后台

**结论**：适合做一期回测内核，外面套一个简单配置界面即可。

## 2.4 RQAlpha（米筐）

- 定位：策略回测/模拟框架
- A股适配：天然面向国内市场
- 优点：
  - A股语义贴近
- 缺点：
  - 生态活跃度与扩展性需评估

**结论**：可作为候选备选方案。

## 2.5 Freqtrade

- 定位：加密量化
- A股适配：弱

**结论**：不建议用于本项目。

## 3. 推荐路线（先系统后策略）

## 路线 A（推荐）：自建“轻中台” + 开源组件拼装

- 数据：AkShare -> PostgreSQL
- 回测：Backtrader
- API：FastAPI
- 配置界面：Streamlit（先）/ Node-RED（后）
- 看板：Metabase

为什么推荐：

- 你现在最需要的是“能用、能改、看得懂”
- 可先手工编辑策略参数并回测
- 后续可无缝加入自然语言转规则（LLM 转 JSON）

## 路线 B：Qlib 为主平台

- 适合模型研究导向团队
- 不太适合你当前“先易用系统再研究策略”的阶段

---

## 4. 一期系统能力边界（建议）

一期只做 4 件事：

1. **策略配置管理**（表单参数，不写代码）
2. **回测执行**（按时间区间、一键运行）
3. **结果展示**（收益、回撤、换手、持仓）
4. **任务调度**（每日收盘后跑一次）

暂不做：自动下单、复杂机器学习、实时高频。

---

## 5. 策略编辑的形式（你可手动编辑）

采用 JSON/表单双形态：

- 界面上你看到中文字段（如“ROE最小值”）
- 系统内部保存为结构化 JSON

示例（概念）：

```json
{
  "universe": {"exclude_st": true, "min_list_days": 250},
  "fundamental": {"roe_min": 12, "pe_min": 8, "pe_max": 30},
  "technical": {"ma20_above_ma60": true},
  "rebalance": {"freq": "weekly", "hold_count": 10},
  "risk": {"max_position": 0.1, "stop_loss": 0.08}
}
```

后续你用自然语言描述时，我可以帮你自动生成这个 JSON。

---

## 6. 建议的实施顺序（3个里程碑）

### M1：系统可用（1~2周）

- 跑通数据同步
- 完成策略配置 CRUD
- 完成回测任务接口

### M2：系统可操作（2~4周）

- 完成界面化策略编辑
- 完成回测结果可视化
- 完成定时任务

### M3：系统可协同（4周+）

- 增加自然语言 -> 策略JSON助手
- 增加策略模板库（价值、趋势、动量、低波）

---

## 7. 你现在最小决策集（只需拍板）

1. 一期采用路线 A 还是 B（建议 A）
2. 界面先用 Streamlit 还是 Node-RED（建议 Streamlit）
3. 调仓频率优先周频还是日频（建议周频）
4. 一期是否只做“人工确认后运行”（建议是）

你只要给这 4 个答案，系统架构就能定稿并进入实现。
